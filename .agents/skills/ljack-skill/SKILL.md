# 엘잭 스킬 (LJack Protocol)
## 범용 런타임 하네스 엔지니어링 & 초자율 에이전틱 개발 프로토콜 (v5.4.0)

> **💡 시스템 지침 (System Directive)**:  
> 본 스킬은 소프트웨어 개발 시 AI 에이전트가 사소한 확인을 위해 중간에 멈추지 않고, 견고한 **[설계 ➔ 코딩 ➔ 빌드 ➔ 자체 테스트 ➔ 자가 치유(Self-Healing) ➔ 종합 감사 ➔ 패키징]**까지 단일 흐름으로 완주하도록 규정하는 최상위 아키텍처 및 자율 실행 프로토콜입니다.

## 1. 런타임 하네스 엔지니어링 8대 핵심 기둥

하네스(Harness)는 핵심 비즈니스 로직이 외부의 불확실한 입력과 예외 속에서도 안전하고 예측 가능하게 구동되도록 감싸주는 **실행 및 검증 뼈대(Runtime & Test Rig)**입니다.

```text
[외부 세계: UI, 웹 클라이언트, 센서, 네트워크 I/O, DB, 렌더링 캔버스]
           │ (Loose Coupling / 이벤트 델리게이트 / 인터페이스)
┌──────────▼─────────────────────────────────────────────────┐
│              런타임 하네스 코어 (Runtime Harness)           │
│                                                            │
│  1. 코어와 입출력 분리 (Decoupling Core from I/O)           │
│  2. 슈퍼바이저-워커 모델 (Supervisor Loop & Async Worker)   │
│  3. 명시적 FSM 상태 머신 & 블랙보드 컨텍스트               │
│  4. 제로 부하 동결(Pause) & 긴급 비상정지(Emergency Stop)  │
│  5. 다중 뷰 조작 일관성 & 상태 불변성 (Interaction Invariance)│
│  6. 물리적 입력 자가 치유 & 저수준 훅 인터록 (Input Safety) │
│  7. 릴리즈 아티팩트 청결화 & 서페이스 격리 (Sanitization)   │
│  8. 선제적 맹점 레이더 & 폐루프 엔지니어링 (Closed-Loop Timing)│
└──────────┬─────────────────────────────────────────────────┘
           │ (GUI/네트워크 없이 메모리 상에서 초고속 검증)
[헤드리스 자체 테스트 러너 (Headless Self-Test Runner)]
```

### 기둥 1: 코어와 입출력의 분리 (Decoupling Core from I/O)
- 비즈니스 코어(상태, 연산, 정책)는 UI 위젯, 특정 하드웨어 드라이버, 외부 API 클라이언트와 강결합하지 않는다.
- 모든 외부 상호작용은 인터페이스(Interface), 이벤트(Event), 델리게이트(Callback)로 분리하여 모킹(Mocking) 및 독립 교체가 가능해야 한다.

### 기둥 2: 슈퍼바이저-워커 실행 모델 (Supervisor-Worker Model)
- 메인 루프는 가볍고 빠른 주기로 상태와 규칙을 평가하는 **감독관(Supervisor)** 역할을 수행한다.
- I/O 대기, 네트워크 지연, 장기 연산 등 블로킹을 유발하는 작업은 메인 루프를 멈추지 않고 별도의 비동기 태스크(Worker)로 분기 실행한다.

### 기둥 3: 명시적 상태(FSM)와 공유 컨텍스트(Blackboard)
- 시스템의 현재 상태(`CurrentState`)와 런타임 공유 데이터(`Context / Blackboard`)를 하네스 코어가 안전하게 단일 소유(Single Source of Truth)한다.
- 상태 전이(Transition Rule)와 조건 평가 파이프라인을 체계화하여 상태 충돌과 레이스 컨디션을 원천 방지한다.

### 기둥 4: 무부하 라이프사이클 및 안전 인터록 (Lifecycle & Safety Interlock)
- **일시정지/재개 (Pause/Resume)**: 비효율적인 폴링 루프 대신 OS 동기화 이벤트(또는 프레임워크 동기화 기제)를 활용하여 메모리를 보존한 채 CPU 점유율 0%로 엔진을 동결한다.
- **최우선 비상정지 (Emergency Stop)**: 어떤 복잡한 비동기 작업이 돌고 있더라도 최우선 순위로 모든 브랜치를 즉각 안전 차단하는 소프트웨어 인터록을 외곽에 구축한다.

### 기둥 5: 다중 뷰 조작 일관성 및 상태 보존 (Interaction Invariance)
- 다중 뷰 모드(예: 캔버스 뷰, 테이블 뷰, 트리 뷰 등)가 제공되는 애플리케이션의 경우, 특정 뷰에서만 단축키나 액션이 누락되는 파편화를 방지하고 공통 인터랙션 인터페이스를 강제한다.
- 뷰 전환 시 사용자의 스크롤 위치, 줌/팬 배율, 선택 항목이 초기화되지 않고 100% 보존되는 뷰 상태 불변성을 유지한다.

### 기둥 6: 물리적 입력 자가 치유 & 저수준 훅 인터록 (Physical Input Safety & Hook Rig, v5.3.0 신설)
- **물리적 입력 먹통(Stuck) 방지**: 키보드/마우스 누름 유지(Hold) 및 드래그 지원 시, 전역 활성 입력 추적기를 구축하고 정지/일시정지/비상탈출/예외 시 100% 강제 해제하는 자가 치유 인터록을 구현한다.
- **저수준 훅 가로채기 & 세션 바인딩**: 단축키 오입력 차단을 위해 OS 저수준 훅에서 제어키를 즉각 가로채며, 비동기 세션 시작 시 대상 엔티티를 강력 바인딩하여 포커스 상실 시 데이터 유실을 방어한다.

### 기둥 7: 릴리즈 아티팩트 청결화 & 프로덕션 UI 서페이스 격리 (Release Sanitization, v5.3.0)
- **프로덕션 UI 서페이스 격리**: 개발자/CI 검증용 Mock 테스트 하네스는 내부 테스트 러너에서만 호출되도록 격리하고, 최종 사용자 UI 콤보박스나 메뉴에는 프로덕션 실제 옵션만 노출한다.
- **배포 아티팩트 자동 청결화**: 배포 스크립트 실행 시 publish 후 테스트를 거치더라도, 패키징 직전에 모든 테스트 출력 로그(`test_*.log`, `*.tmp`)를 자동 소거하여 배포 ZIP 내 불필요한 파일을 0건으로 보장한다.

### 기둥 8: 선제적 맹점 레이더 & 폐루프 엔지니어링 (Proactive Blind-spot Radar & Closed-Loop Rig, v5.4.0 신설)
- **폐루프 틱 & 시간 드리프트 제어 (Closed-Loop Timing)**: 연산 시간과 OS 타이머 해상도(15.6ms)로 인해 시간이 끝없이 밀리는 개루프(Open-Loop `Sleep`)를 배제하고, 오차를 측정하여 다음 대기에 감산 반영(`Target - Work - Drift`)하는 자가 치유 폐루프를 구축한다.
- **선제적 맹점 발굴 및 자동 감시 (Blind-spot Radar)**: 사용자가 배경지식이 없어 묻지 못하는 시스템/OS/하드웨어 제약, 자원 누수, 교착 상태 등 숨겨진 맹점(Unknown Unknowns)을 정적 린터(Radar Inspector) 및 최종 보고서에서 능동 제시한다.

## 2. 초자율 에이전트 실행 강령 (Autonomous Directives)

AI 에이전트가 작업을 수행할 때 반드시 준수해야 하는 행동 규칙입니다.

1. **완료 조건은 '사용자 응답'이 아니라 '자체 검증 ALL PASS'다.**
   - 단순히 파일 몇 개를 생성한 뒤 "어떻습니까?"라고 물으며 멈추지 않는다.
   - 프로젝트에 정의된 Headless 자체 테스트 러너 및 종합 감사 스크립트가 100% 통과하여 결함 0건이 될 때까지 자율적으로 작업을 지속한다.

2. **무중단 자가 치유 루프 (Self-Healing Loop)**
   - 컴파일 경고/에러, 런타임 예외, 테스트 실패가 발생하면 사용자에게 어떻게 할지 묻지 않는다.
   - 터미널 출력과 스택 트레이스를 스스로 역추적하여 원인을 분석하고, 코드를 직접 재수정하여 빌드와 테스트가 통과할 때까지 자율적으로 수정을 반복한다.
   - 땜질식 핫픽스가 아니라 시스템 아키텍처 수준에서 재발을 방지하는 구조적 해결책을 적용한다.

3. **마이크로 디시전 자율화 (Micro-Decision Autonomy)**
   - 변수 명명, 내부 헬퍼 함수 구조, UI 여백, 사소한 컴포넌트 배치 등 개발 상식선에서 판단 가능한 사안은 에이전트가 직접 최선의 결정을 내린다.

4. **사전 승인 관문 및 최소 개입 (Human-in-the-Loop & Approval Gate)**
   - 대규모 기능 구현이나 아키텍처 변경 전 요구사항 이해도를 점검받은 후(Approval Gate), 구현 착수 후에는 오직 다음 2가지 상황에서만 사용자에게 응답을 요구한다:
     1. 전체 시스템이 완성되어 모든 자체 테스트와 품질 감사를 ALL PASS로 통과했을 때 (최종 보고).
     2. 비즈니스 기획상 상충되어 사용자의 방향성 선택이 불가피할 때.

5. **물리적 입력 자가 치유 및 세션 바인딩 준수**
   - 하드웨어 제어/입력 주입 시 비정상 종료로부터 사용자의 물리적 입력을 보호하고, 비동기 작업 시 대상 참조가 유실되지 않도록 컨텍스트 바인딩을 강제한다.

6. **배포 패키징 청결도 및 UI 서페이스 격리 준수**
   - 개발용 테스트 출력 로그가 배포 패키지나 ZIP 파일에 누출되지 않도록 자동 소거하고, Mock 하네스를 프로덕션 UI 서페이스에서 완전 격리한다.

7. **선제적 맹점 발굴 및 사전 보고 강제 (Proactive Blind-spot Surfacing, v5.4.0 신설)**
   - 에이전트는 사용자가 요구한 기능을 완주한 후, 사용자가 배경지식이 없어 놓칠 수 있는 **[숨겨진 시스템/OS 제약, 타이머 해상도/드리프트, 메모리 누수, 동시성 병목 등 Unknown Unknowns]**를 1~2가지 선제적으로 발굴하여 최종 완료 보고 시 `[🔭 시니어 아키텍트 관점의 잠재 맹점 / 개선 레이더]` 섹션으로 반드시 보고해야 한다.

## 3. 개발자-AI 페어 프로그래밍 3대 마법의 검증 질문 (질문 프레이밍)

사용자가 AI에게 맹점을 선제적으로 털어놓게 만드는 3대 검증 트리거 공식입니다:

1. **맹점 발굴**: *"시니어 시스템 엔지니어 입장에서 내가 배경지식이 없어 놓친 OS/하드웨어 레벨의 맹점(Unknown Unknowns)이나 안티패턴 3가지를 짚어줘."*
2. **부하/내구성 검증**: *"이 코드가 프로덕션 환경에서 10만 번 연속으로 돌거나 극단적인 부하를 받으면 가장 먼저 터질 병목이 어디야?"*
3. **아키텍처 비판**: *"이 구현을 시니어 아키텍트 관점의 악마의 대변인(Devil's Advocate) 입장에서 비판해줘."*

## 4. 자율 실행 5단계 표준 파이프라인

```text
[1단계: 요구사항 승인 및 인터페이스 선언]
  - 요구사항 검토 후 프로젝트 뼈대, 핵심 도메인 인터페이스, FSM 상태 명세 정의
       ↓
[2단계: Headless 자체 테스트 러너 구축]
  - GUI나 외부 I/O 없이도 메모리 상에서 로직을 0.5초 만에 검증하는 테스트 스위트 작성
       ↓
[3단계: 비즈니스 로직 및 런타임 하네스 구현]
  - 느슨한 결합, 비동기 워커 분기, 무부하 동결(Pause), 물리 입력 자가 치유 안전망 탑재
       ↓
[4단계: 자가 치유 무한 검증 및 품질 감사 루프]
  - 빌드 ➔ 자체 테스트 실행 ➔ 정적 분석/감사 스크립트 실행
  - ❌ 실패 시: 에러 역추적 ➔ 코드 재수정 ➔ 재검증 (스스로 반복)
  - ✔️ 통과 시: 최종 패키징 단계로 전진
       ↓
[5단계: 원클릭 표준 패키징 및 최종 보고]
  - 배포 스크립트 실행 (버전 자동 감지, 번들링, 테스트 로그 자동 소거, 아티팩트 생성)
  - 결함 0건 확인 후 사용자에게 최종 완료 요약 보고
```

## 5. 다양한 프로젝트 도메인별 적용 가이드

본 스킬은 특정 언어나 프레임워크에 종속되지 않으며 다음과 같이 일반화하여 적용합니다:

* **웹 백엔드 API (FastAPI / NestJS / Spring Boot 등):**
  - *코어 분리:* 비즈니스 도메인 서비스가 HTTP 요청 객체나 ORM에 직접 종속되지 않게 Clean/Hexagonal Architecture 적용.
  - *하네스 검증:* 실제 DB/외부 API 없이 In-Memory Repository와 가상 이벤트 버스를 통한 유닛/통합 테스트 러너 구축.
* **프론트엔드 웹 앱 (React / Vue / Next.js 등):**
  - *하네스 검증:* UI 컴포넌트 마운트 없이 Zustand/Redux 상태 머신 및 액션 디스패처를 검증하는 Headless 테스트 우선 작성.
  - *뷰 일관성:* 모바일/데스크톱 뷰 전환 시 폼 입력 데이터 및 모달 상태 보존.
* **시스템 자동화 / 데스크톱 앱 (WinForms / WPF / Electron / Qt 등):**
