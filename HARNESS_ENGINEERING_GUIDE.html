Harness Engineering Master Guide (v5.0.0 메이저 개정판)

하네스 엔지니어링 실전 아키텍처 및 복습 가이드

소프트웨어 런타임 하네스의 10단계 정착 변천사, 적절성 분석, 그리고 신규 세션 즉시 적용 프롬프트 자산

📌 Part 1. 현재의 하네스 엔지니어링 정착 과정과 적절성 평가

1. 하네스 아키텍처의 8단계 진화 변천사

RpgMacroStudio 프로젝트는 단순한 반복 스크립트에서 출발하여 최고 수준의 에이전틱 거버넌스와 뷰 불변성, UI 렌더링 무결성을 갖춘 완성형 런타임 하네스로 진화했습니다.

1

1단계: 단순 Polling 루프 (Single-Threaded Loop)

화면 캡처 ➔ 색상 비교 ➔ 키 입력을 while(true) 하나로 처리. Sleep(1000) 등 대기 동작 시 화면 감지가 완전히 멈추는 블로킹 병목 발생.

2

2단계: 슈퍼바이저 & 비동기 브랜치 (Supervisor-Worker Pattern)

메인 루프를 감독관(Supervisor)으로 승격하여 빠른 주기로 계속 스캔하고, 시간 소요가 큰 동작(대기, 연타)은 Task.Run 독립 브랜치로 분기. 외곽에 비상정지(EmergencyStop) 인터록 구축.

3

3단계: FSM(유한상태머신) & 블랙보드 룰 엔진

단순 나열식 매크로의 조건 충돌을 극복하기 위해 CurrentState(상태 전이)와 RuntimeVariables(공유 메모리)를 탑재. 다중 조건(비전 + 변수 + 타이머) AND 평가 파이프라인 완성.

4

4단계: 무부하 동결(Pause) 및 헤드리스 자체 검증 하네스

스레드를 파괴하지 않고 ManualResetEvent로 CPU 점유율 0%로 엔진을 동결/재개. 실제 화면/입력 없이도 콘솔 명령어(--test)만으로 엔진을 100% 검증하는 25종 SelfTestRunner 결합.

5

5단계: 통합 계층 표 뷰(Tree-Table) & 브라우저 탭 스타일 3대 뷰 하네스

클래식 목록과 계층 트리를 결합한 [통합 계층 표 뷰]로 UI 일원화. 상단 브라우저 탭 스타일 3대 뷰([📦 FSM], [🔀 핀], [☰ 클래식]) 및 뷰 전환 시 줌/팬 좌표와 작업 상태를 100% 보존하는 뷰 상태 불변성 확립.

6

6단계: 12대 전담 에이전트 종합 감사, 와치독 3종 졸업 실증 & 원클릭 동적 빌더

버전/카피/레이아웃/Janitor/i18n/테마/키보드/패키징/리사이즈/폰트/탭 전환 등 12개 영역을 점검하는 inspect_agents.py, 3대 만성 결함의 3연속 통과 와치독 공식 졸업, 버전 자동 감지 단일 런처 빌더(build_release.py)로 완성.

7

7단계: 모듈형 파셜 클래스 & 초고속 핫루프 검증 (Modular Partial & Hot-Loop)

2,700줄 대형 폼을 4대 파셜 클래스로 분할하여 코드 조회 시 AI 토큰 70% 절감. 빌드 ➔ 자체 테스트 ➔ 12대 감사를 단 5초 만에 완주하는 quick_check.py 개발 피드백 루프 극대화.

8

8단계: WinForms UI 무결성 4대 원칙 & 수식 기반 레이아웃 회귀 하네스 (Zero-Defect UI Rig)

Dock Z-Order 역전, Paint 잔상 누적, AutoSize 불일치 3대 원인을 규명하고, 커스텀 컨트롤 자가 완비, 도킹 컨테이너 격리, 비클리핑 버퍼, 테마 일원화 4대 원칙과 수식 기반 비중첩 레이아웃 회귀 검증(TestInspectorLayout) 체계 확립.

9

9단계: BYOK 멀티 프로바이더 AI 어시스턴트 & 모의 검증 파이프라인 (BYOK Multi-AI Rig)

유저 API 키를 사용하는 BYOK(Bring Your Own Key) 아키텍처로 운영자 비용 손실 0% 보호. 5대 모델(Gemini, Claude, OpenAI, Ollama, Mock) 런타임 자유 전환 및 외부 통신 없는 헤드리스 Mock 클라이언트로 CI 검증 완비.

10

10단계: 완전 적응형 가변 뷰 & 전역 유니코드 합성 렌더링 하네스 (Responsive & Unicode Rig)

가로 스크롤 0% 비례 컬럼 자동 조정, 인스펙터 패널 폭에 연동되는 32px 슬림 버튼 축소(ToolTip 호버 연동), 그리고 Windows GDI+ 글리프 깨짐(□ tófu)을 100% 영구 해결한 유니코드 클러스터 분리 복합 폰트(Segoe UI Emoji + Segoe UI Bold) 합성 렌더링 체계 정립.

2. 현재 방식의 적절성 평가 (왜 가장 이상적인가?)

🛡️ 1. 회귀 방어력 100% (Zero-Regression) FSM 카드 뷰, 핀 그래프 뷰, 통합 계층 표 뷰 등 복잡한 뷰 모드가 상호작용함에도, 25개 전수 자체 테스트가 매 빌드마다 엔진 무결성을 0.5초 만에 검증하여 기존 기능의 파괴를 원천 차단합니다.
🏗️ 2. 구조적 근본 해결 (Architectural Integrity) 단순히 눈앞의 에러 한 줄을 땜질하는 것이 아니라, F2/Delete/Enter/Space 단축키를 공통 이벤트 라우팅 구조로 묶고 노드 연결 모델을 데이터 레벨에서 안전화하여 다시는 같은 문제가 발생하지 않도록 최적화합니다.
🎯 3. 뷰 불변성 및 독립 좌표계 (View Invariance) FSM 뷰와 핀 뷰가 서로의 노드 크기와 확대 비율을 오염시키지 않도록 독립 줌/팬 오프셋을 유지하고, 뷰 전환 시 선택 인덱스와 스크롤 위치를 온전히 보존하여 사용자 경험의 일관성을 극대화합니다.
🚦 4. 12대 에이전트 감사 및 자동 빌드 거버넌스 코드 수정 전 사용자 승인(Approval Gate)을 거치고, 12대 전담 에이전트 종합 감사(inspect_agents.py)를 통과한 뒤에만 원클릭 릴리즈 빌더(build_release.py)로 배포하므로 결함 유출이 0%로 통제됩니다.
📐 5. UI 무결성 4대 원칙 및 수식 기반 레이아웃 방어 (Zero-Defect UI) 눈대중이나 임시 픽셀 땜질 대신 컨트롤 자가 완비(GetPreferredSize + Paint 배경 클리어), 도킹 컨테이너 격리, 텍스트 비클리핑 버퍼를 적용하고, 컨트롤 비중첩(Right <= Left)과 충분 폭을 수학적 부등식으로 자동 검증합니다.
🤖 6. BYOK 멀티 프로바이더 AI 아키텍처 (BYOK Multi-AI Rig) 사용자 API 키 기반 BYOK 아키텍처로 운영자 비용 손실을 0%로 차단하고, 5대 프로바이더(Gemini, Claude, OpenAI, Ollama, Mock) 공통 인터페이스 추상화 및 외부 통신 없는 헤드리스 Mock 클라이언트로 CI 검증을 완비합니다.
🎨 7. 완전 적응형 가변 뷰 & 유니코드 복합 폰트 합성 렌더링 (Responsive & Unicode Rig) 인스펙터 폭에 연동되는 32px 슬림 버튼 축소(ToolTip 호버 연동)와 Windows GDI+ 글리프 깨짐(□)을 영구 해결한 Segoe UI Emoji(Regular) + Segoe UI(Bold) 유니코드 클러스터 분리 합성 렌더링(DrawMixedString)으로 모든 해상도에서 무결한 UI를 보장합니다.

🚀 Part 2. 새 세션/프로젝트에서 동일한 프로세스를 적용하는 방법

새로운 세션에서 웹 백엔드, 앱, 데스크톱 툴 등 다른 종류의 소프트웨어를 개발할 때 아래 자산들을 그대로 활용하세요.

자산 1. 새 세션 시작 시 AI에게 주입할 "마스터 시스템 프롬프트"

새 대화창을 시작할 때 가장 먼저 전송하여 AI의 설계 방향성을 하네스 엔지니어링으로 고정시키는 프롬프트입니다.

Master Prompt Template 
[시스템 아키텍처 및 런타임 하네스(Runtime Harness) 개발 지침 (v5.0.0)]

우리는 지금부터 {프로젝트 이름 / 구현할 시스템}을 함께 개발할 것입니다.
단순히 동작만 하는 일자형 코드가 아니라, 신뢰성과 확장성이 높은 "런타임 하네스(Runtime Harness) 엔지니어링" 방식으로 설계하고 개발해주세요.

다음의 7대 개발 원칙을 반드시 준수해야 합니다:

1. 하네스 코어와 입출력 분리 (Loose Coupling & Supervisor)
   - 핵심 비즈니스 로직(판단/연산/상태)은 외부 입출력(UI, 센서, DB, 하드웨어)과 강하게 결합되지 않고 인터페이스/이벤트로 분리되어야 합니다.
   - 장기 실행 작업이 메인 슈퍼바이저 루프를 블로킹하지 않도록 비동기 브랜치(Worker Task) 모델을 적용하세요.

2. 상태(FSM) 및 블랙보드 메모리 컨텍스트
   - 시스템의 현재 상태(CurrentState)와 공유 런타임 메모리(Blackboard)를 코어가 안전하게 소유하고, 예측 가능한 상태 전이를 지원해야 합니다.
   - 다중 조건(센서 + 변수 + 타이머)을 AND 결합으로 평가하고, 안전한 상태 전이를 수행하세요.

3. 생명주기 및 인터럽트 제어 (Lifecycle & Safety Interlock)
   - 시작/정지 외에 상태와 변수를 메모리에 보존하며 CPU 점유율을 0%로 동결하는 일시정지/재개(ManualResetEvent 기반)를 구현하세요.
   - 최우선 비상정지(Emergency Stop) 인터록을 연결하여 언제든 즉시 안전 차단이 가능하도록 해주세요.

4. 전 뷰 조작 일관성 및 시각 피드백 (Universal View Invariance)
   - 다중 뷰 모드가 존재할 때 단축키(F2 편집, Delete 삭제, Enter 열기, Space 토글)가 모든 뷰에서 동일하게 작동해야 합니다.
   - 뷰 모드 전환 시 줌/팬 좌표계와 선택 상태가 초기화되지 않고 100% 보존되도록 독립 좌표계를 유지하세요.

5. BYOK 멀티 프로바이더 AI 엔진 결합 (v5.0.0 신설)
   - AI 기능 도입 시 유저 본인의 API 키를 입력하는 BYOK 구조를 적용하여 운영자 비용 손실을 0%로 차단하세요.
   - 멀티 프로바이더(Gemini, Claude, OpenAI, Ollama, Mock)를 단일 인터페이스로 추상화하고, 외부 통신 없는 헤드리스 Mock 클라이언트로 CI 검증을 완비하세요.

6. 반응형 UI 가변 적응 및 유니코드 복합 폰트 렌더링 (v5.0.0 신설)
   - 가용 패널 너비에 따라 버튼이 자동으로 32px 슬림 정사각형 아이콘(ToolTip 호버 연동)으로 축소되는 반응형 레이아웃을 구축하세요.
   - Windows GDI+에서 기호/이모지가 네모(□)로 깨지지 않도록, 유니코드 클러스터를 분리하여 Segoe UI Emoji(Regular)와 Segoe UI(Bold)로 합성 렌더링(DrawMixedString)하세요.

7. 관측성, 12대 에이전트 감사 및 자동 빌드 파이프라인
   - GUI 없이도 콘솔 명령어(--test)로 로직 및 수식 레이아웃을 1초 만에 검증하는 SelfTestRunner를 코어와 동시 구축하세요.
   - 버전, 다국어, 레이아웃, 단축키 일관성을 전수 점검하는 inspect_agents.py와 5초 핫루프 quick_check.py를 상시 유지하세요.
   - 동적 버전 감지 및 단일 런처 패키징을 수행하는 build_release.py를 구축하세요.

자산 2. 프로젝트 초기에 구축할 '검증 파이프라인 4종 세트'

프로젝트 착수 직후 AI에게 다음 4개 파일(모듈)을 반드시 구성하도록 지시하세요.

1. SelfTestRunner (코어 엔진 단위/통합 테스트 스위트) 외부 UI나 네트워크 없이 비즈니스 로직 25~30가지를 메모리 상에서 0.5초 만에 테스트하는 러너. (예: myapp --test)
2. inspect_agents.py (12대 전담 에이전트 종합 감사 스크립트) 버전 일치성, 텍스트 잘림, UI 정합성, 번역 누락, 클린업, 키보드 인터랙션, 폰트 무결성, 패키징 상태를 전수 조사하여 ALL PASS / FAIL을 출력하는 감사관.
3. watchdog_state.json (학습/졸업형 오류 감시 와치독) 개발 중 자주 재발하는 엣지 케이스를 등록하고, 3회 연속 통과 시 감시를 자동 졸업(Graduation)시켜 AI 토큰을 절약하는 최적화 장치.
4. build_release.py (원클릭 표준 릴리즈 빌더) 소스 버전 동적 감지, 루트 경로 단일 런처 배치, data/ 서브폴더 격리, 자체 검증 통과 확인, ZIP 배포 파일 생성을 단일 명령으로 완료하는 배포 하네스.

자산 3. 세션 진행 중 사용하는 "협업 및 유지보수 규칙 4대 패턴"

대화 도중 아래의 표준 요구 패턴을 사용하시면 AI가 스스로 높은 품질 기준을 유지합니다.

패턴 1. 새 기능 추가 시 (테스트 동시 작성)
"이 기능을 추가하되, 기존 SelfTestRunner에 이 기능의 엣지 케이스를 검증하는 테스트 케이스도 함께 추가해줘."
패턴 2. 버그 수정 시 (단순 땜질 금지 & 구조적 차단)
"단순히 이 코드 한 줄만 고치지 말고, 아키텍처 수준에서 왜 이런 일이 생겼는지 분석하고 다시는 재발하지 않도록 구조를 최적화해줘."
패턴 3. 작업 착수 시 (승인 게이트 & 릴리즈 통제)
"바로 수정하지 말고 내가 말한 요구사항을 정확히 이해했는지 나한테 먼저 확인받고 시작해줘. 빌드와 12대 에이전트 감사를 통과하기 전엔 릴리즈하지 마."
패턴 4. UI 텍스트 짤림/겹침 발생 시 (근본 원인 3종 진단 & 수식 회귀 검증)
